# MeetSpot 项目体检与比赛优化清单

体检时间：2026-08-07。结论：核心链路可用，但有三处比赛致命风险，按优先级排列。

## P0 必须处理（复赛前）

### 1. 线上 Demo 免费额度只有 1 次

实测：第一个请求成功，第二个请求返回"Daily free quota exhausted. Please purchase credits to continue"。来源是 api/index.py:376 的 `FREE_DAILY_LIMIT` 环境变量，默认 1。

影响：评委或评审访问线上 Demo 时，一次演示后其他人就无法再试。

处理决定（2026-08-07）：暂时调整为每天 2 次，部署环境（Render）设置 `FREE_DAILY_LIMIT=2`。如果评审期需要更多，直接改成 0 即完全关闭。这是部署配置变更，交给 Claude Code 执行。

### 2. 单个地址解析失败会导致整个请求失败

代码路径 app/tool/meetspot_recommender.py:790 至 802：任一地址 geocode 失败时直接返回错误，已成功的地址也不继续。

对应 Issue #48（其中一个地址解析错误）和 #50（找不到地址）的同类根因。

处理状态（2026-08-07 已完成）：已改为部分成功策略，失败地址单独提示并跳过，其余地址继续完成推荐；全部失败时保留详细输入建议。新增 tests/test_geocode_failure.py 覆盖。

### 2.1 线上 Agent 模式被硬编码禁用

api/index.py:59 `agent_available = False  # 禁用 Agent 模式，节省内存`，导入 Agent 模块的代码被注释掉。实测 `/api/find_meetspot_agent` 返回的是规则模式结果，复杂度路由的 `use_agent` 永远为 False。

影响：简介和 PPT 宣称"规则模式与 Agent 模式间自主选择"，但线上 Demo 实际只走规则模式。评委很容易用复杂请求验证，属于"展示与承诺不符"红线风险。

处理状态（2026-08-07 代码已完成）：已解除硬编码禁用，Agent 模块导入成功即启用，失败自动降级规则模式。部署到线上后需 Claude Code 用浏览器验证内存与稳定性。

### 3. 核心引擎没有回归测试

现有测试只有 2 个文件 16 个用例，全部通过，但没有覆盖推荐主流程、geocode 失败分支、回退搜索、配额逻辑。

处理状态（2026-08-07 已完成第一版）：测试从 16 个增至 27 个，新增部分失败、全失败、Agent 可用性、复杂度路由、配额禁用与拦截、配置脱敏等用例。
