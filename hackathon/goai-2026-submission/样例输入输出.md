# MeetSpot 样例输入输出

版本：v1.0（2026-08-07）

用于复赛 Demo 演示和评测，后续扩展为 BENCHMARK.md 的基线样例。

## 样例 1：三人聚餐（规则+LLM 模式）

输入：

- 地点：北京市海淀区中关村大街27号、北京市朝阳区建国路88号、北京市西城区西单北大街120号
- 场所：咖啡馆
- 需求：安静

实测输出（2026-08-07 线上）：

- 结果：6 家咖啡馆推荐，含评分与地址
- 耗时：12.4 秒
- 模式：rule_llm，复杂度 15 分（3 个地点）
- 交付：推荐文本 + 地图结果页

## 样例 2：复杂需求触发 Agent 模式（构造）

输入：

- 地点：4 个跨城区地址
- 场所：咖啡馆 餐厅 茶馆
- 需求：安静 有停车位 人均50元内

预期输出：

- 模式：agent，复杂度不低于 40 分
- 结果：3 至 5 个推荐，含每人的距离对比和推荐理由
- 超时或失败时自动降级规则模式并给出说明

注意：该场景需部署端确认 LLM key 与 Agent 模式可用后实测记录。

## 样例 3：单个地址解析失败（部分成功）

输入：

- 地点：地点甲、无法识别的地点乙、地点丙
- 场所：咖啡馆

预期输出（2026-08-07 已实现并有测试）：

- 请求不中止，基于地点甲与地点丙继续推荐
- 文本与结果页提示"1 个地址解析失败，已跳过：无法识别的地点乙"

## 样例 4：全部地址解析失败

输入：

- 地点：两个无意义字符串

预期输出：

- 明确错误：未能解析任何有效的地点位置
- 每个失败地址附输入建议（完整地址、地标、商圈等格式示例）

## 样例 5：POI 无结果回退

输入：

- 地点：两个正常地址
- 场所：小众关键词（如茶馆）
- 周边无茶馆

预期输出：

- 依次回退：无类型限制搜索、类别回退（餐厅/咖啡馆/商场/美食）、扩大半径
- 最终推荐回退类别并提示"已为您推荐附近的「餐厅」"
- 全部失败时给出"在该区域未能找到任何推荐场所"

## 本地端到端实测记录（2026-08-07）

环境：本地 uvicorn + 真实高德 key，FREE_DAILY_LIMIT=0，本地 LLM key 为已封禁状态（用于验证降级）。

场景 A（部分失败）：2 个北京地址 + 1 个乱码地址。

- 结果：success=True，返回 6 家咖啡馆
- 文本明确提示：Note: 1 address(es) could not be parsed and were skipped: qwertyuiopasdfghjkl
- 耗时：15.5 秒（受本地 LLM key 重试拖慢）

场景 B（复杂请求触发 Agent 后降级）：4 个北京地址 + 3 种场所 + 2 个需求，复杂度 70 分。

- 结果：success=True，mode=rule_llm
- 日志显示：[Agent] 执行超时(15秒)，降级到规则模式
- 耗时：30.6 秒（Agent 等待 15 秒 + 规则路径 LLM 重试）

场景 C（强制 Agent 接口）：2 个北京地址。

- 结果：success=True，mode=rule_fallback
- agent_error：RetryError PermissionDeniedError（本地 LLM key 被封的明确定位）
- 说明：换成有效 LLM key 后该路径应返回 agent 模式，降级机制已由单元测试覆盖

结论：核心链路、失败分支、Agent 降级全部可用；线上部署后需用有效 LLM key 复测 agent 模式与耗时。

## DeepSeek 切换后实测（2026-08-07）

- 规则路径：2 个北京地址，5.1 秒返回 6 家咖啡馆，交通建议由 DeepSeek 真实生成（日志：LLM 生成了 3 条交通建议）
- 强制 Agent 接口：2 个北京地址，5 步完整跑通，mode=agent，输出含公平性评分与 TOP 5 推荐；耗时 29.8 至 71 秒波动（DeepSeek 偶发空响应触发重试）
- 自动路由复杂请求：复杂度 70 分进入 Agent 尝试，25 秒超时后降级规则模式，最终仍返回推荐
- 结论：DeepSeek 切换成功；现场演示建议用规则路径或强制 Agent 接口，路由路径依赖降级兜底
