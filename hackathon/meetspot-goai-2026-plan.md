## 1. 参赛定案

### 1.1 赛道与主题

赛道：无界应用（Boundless Agents）。

主题：AI+本地生活服务，细分场景为多人线下协作决策。

项目名：MeetSpot。

一句话定位：MeetSpot 是一个面向多人线下协作场景的自主决策 Agent，输入各方位置与需求，自主完成公平中心计算、地点检索、多因子评分和可解释推荐，把"在哪见"从个人偏好搜索变成全体可验证的公平决策。

赛道契合依据：无界应用官方摘要原文为"面向真实产业、社会和生活服务场景"，选题说明原文为"以下方向用于帮助理解赛道定位，不限制参赛作品的具体创意边界"，并明确允许"基于真实需求提出与赛道定位一致的细分场景"。MeetSpot 按自拟细分场景申报，定位为本地生活服务的多人线下协作决策，不硬套眼镜、汽车、金融、教育、工业制造五个方向。

### 1.2 目标口径

现实目标：进入赛道复赛（Top 30）与决赛（Top 15），争取赛道奖项。

冲刺目标：赛道冠军 50 万元。

诚实说明：100 万全场大奖的评选口径是开源影响力、跨领域复用价值、未来成长潜力，结构上偏向基础设施类项目。MeetSpot 作为应用类项目拿到全场大奖的概率低，方案不以此为目标，但材料中会尽量强化复用价值叙事，不主动放弃。

### 1.3 决策依据

- 用户熟悉度最高，执行风险最低。
- 线上 Demo 活着，演示视频、文档、CI、License 全部现成。
- 项目保持活跃迭代（最近提交 2026-08-07）。
- 523 星、58 fork，是 GitHub 上社区验证最强的个人项目。
- 初赛只需 500 字简介加 PPT，8 月 16 日截止前工作量可控。

## 3. 差异化策略

### 3.1 核心差异化

MeetSpot 不是地图搜索，而是"公平性决策引擎"：

- 决策目标不同：传统工具按个人位置就近返回，MeetSpot 计算多方公平中心
- 过程可解释：五步推理链，评委和用户都能看到推荐理由
- 能力可扩展：公平中心计算、多因子评分、需求解析可拆成组件，复用到其他多人决策场景

### 3.2 叙事升级

从"聚会找地方"升级为"多人线下协作决策"，目标用户分三层：

1. C 端：学生社团、亲友聚会，高频入口
2. B 端：企业团建、异地客户约见、HR 活动组织，有工作流和预算
3. 平台端：本地生活决策引擎，可被第三方应用二次开发

初赛材料以第 1 和第 2 层为主，第 3 层讲开放价值。

现有生活服务类助手多为单人查询，多人群体决策是空白点，也是差异化叙事核心。

### 3.3 必须避免的叙事

- "推荐系统"
- "聚会工具"
- "地图应用"
- 泛聊天

### 3.4 评委必答三问

1. 你的行业场景是什么？回答：本地生活服务的多人线下协作决策，覆盖聚会、企业团建、异地客户约见和远程团队碰面，属于无界应用赛道的生活服务细分场景
2. 谁为它付费？回答：B 端场景的 HR、销售运营、活动组织者；C 端免费引流
3. 为什么不用地图 App？回答：地图只解决"从哪出发"，不解决"大家去哪公平"，MeetSpot 解决的是群体决策问题

## 8. 附件 A：500 字作品简介草稿

项目名称：MeetSpot 多人会面公平决策智能体
所选行业赛题：无界应用（自拟细分场景：多人线下协作决策）。

问题与场景：多人线下约见时，地点选择耗时且众口难调。现有地图工具只按个人位置就近返回结果，缺乏公平性和全局视角。场景覆盖校园聚会、企业团建、异地客户约见和远程团队线下碰面。

核心解决方案：MeetSpot 是一个自主决策 Agent。输入多方位置与需求后，自主完成地址解析、公平中心计算、POI 检索、多因子评分与可解释推荐，形成从任务理解到结果交付的完整闭环；通过复杂度路由在规则模式与 Agent 模式间自主选择。

创新点与差异化：以"公平性"为决策目标而非就近搜索；五步可解释推理链让推荐结果可追溯；规则评分与语义评分双通道融合；支持 350+ 城市、12 类场所主题和 2 至 10 人规模。

开放与复用价值：MIT 开源，Docker 一键部署，双语文档与 API 文档齐全；地址解析、公平中心计算与评分引擎可拆分为可复用组件，供本地生活决策类应用二次开发。

当前进展：线上 Demo 稳定运行，覆盖 350+ 城市；已获 500+ GitHub Stars，社区持续反馈；下一步接入企业会议规划场景与多轮协商能力。
